# 도티두잇 홈페이지 구성 초안

2026-10-28 작성. 홈페이지의 첫 역할은 도티두잇을 모르는 사람이 자신의 생활에 어떻게 써볼지 이해하도록 돕는 것이다. 설치 전에 미션·루틴·기록의 차이를 설명하고, 설치 후에는 필요한 사용법을 다시 찾아볼 수 있게 구성한다.

## 소개 방향

핵심 문장: **하고 싶은 일을, 오늘의 실천으로.**

설명 문장: **목표를 정하고, 루틴을 따라 실천하고, 나의 기록을 돌아보세요. 걷기부터 운동, 부모님께 마음 전하기까지 도티두잇에서 시작할 수 있습니다.**

방문자를 기록에 익숙한 사람으로 가정하지 않는다. 첫 화면에서는 미션·루틴 같은 앱 용어에 앞서 걷기, 운동, 마음 전하기 같은 생활 장면을 보여준다. 이어서 미션은 이루고 싶은 일, 루틴은 수행 순서, 기록은 남겨둔 결과라는 관계를 설명한다.

브랜드 이야기는 대표님의 요청에서 추론한 제안이다. 실제 창업 일화, 대표님 인용, 이용자 후기, 검증하지 않은 성과 수치는 만들지 않는다. 근거와 해석은 [편집 근거](editorial-basis.md)에 구분했다.

## 홈 화면 순서

1. 소개 문구와 실제 앱 화면, ‘도티두잇 시작하기’ 및 ‘사용 방법 살펴보기’ 버튼.
2. 생활 속 예시: 걷기, 근력 운동, 달리기, 부모님께 마음 전하기.
3. 사용 흐름: 목표 정하기 → 실천하기 → 기록 돌아보기.
4. 내 상황에 맞는 기록: 측정, 직접입력, 지원 항목의 자동기록.
5. 순서대로 따라 하는 루틴과 구성 미리보기.
6. 기록카드·사진·메모, 미션 없이 쓰는 피드.
7. 만든 이유의 짧은 소개와 자세한 이야기 링크.
8. 주요 질문과 설치 안내.

휴대폰에서 읽기 좋은 한 열 구성을 우선한다. 본문은 읽기 편한 폭으로 제한하고, 자세한 내용은 접힌 영역에만 숨기지 않는다. 화면 이미지 속 글자와 별개로 설명을 실제 본문 텍스트로 제공한다.

| 홈 | 미션 목록 | 걷기와 운동, 관계를 위한 실천이 함께 있다는 점 |
| 미션 | 미션 상세와 결과 입력 선택 | 목표·진행 현황과 기록 방법 |

| 기록 | 수행 히스토리와 기록카드 | 날짜별 결과와 사진·메모 |
| 가이드 | 설명하는 단계의 실제 화면 | 글과 화면의 조작 위치 일치 |

공개용으로 준비한 예시 데이터를 사용한다. 실제 사용자 사진·계정·GPS 경로가 들어간 개발 캡처는 사용하지 않는다. 첫 디자인에서는 앱의 주황색 ‘잇’ 로고와 현재 앱 색상 자산을 확인해 일관되게 적용한다.

## 검색과 유지 관리

각 문서의 제목·설명은 아래 원고에 준비했다. 한 페이지는 한 가지 핵심 질문을 충분히 설명하고, 관련 설명은 링크로 연결한다. 별도 주소를 가진 안내 문서를 정적 HTML로 읽을 수 있는 형태로 구현하는 방향을 우선한다. 프레임워크는 화면 구현을 시작할 때 정한다.

‘미션 앱’, ‘운동 루틴 타이머’, ‘걸음수 기록’ 같은 표현은 실제 기능을 설명하는 맥락에서 쓴다. 이 표현들의 검색량이나 순위는 조사한 것으로 간주하지 않는다. 글자 수 목표나 검색 순위 보장은 두지 않는다.

도메인을 정한 뒤 canonical URL·사이트맵·robots·공유 미리보기와 검색 도구 등록을 진행한다. URL과 앱스토어 주소는 실제 주소를 확인해 설정한다. 법적 고지·문의처는 기존 공식 자료를 연결하고 새로 지어내지 않는다.

현재 원고의 `status: draft`는 편집용 표시다. 구현된 사이트 생성기는 초안을 공개 빌드에서 제외하며, 로컬 미리보기에서만 검색 수집 차단 설정과 함께 보여준다. GitHub Pages 자동 배포는 [배포 안내](github-pages.md)에 정리했다.
