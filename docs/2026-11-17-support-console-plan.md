# 도티모티 문의 관리 연결 검토

사용자 질문: 도티모티 앱의 문의를 홈페이지 관리자 화면에서 종합하고 담당자가 답변할 수 있는가?

가능하다. 홈페이지는 현재 GitHub Pages의 정적 사이트이며, 문의 본문·계정·답변은 공개 HTML이나 저장소에 보관하지 않고 인증된 서버 API에서 관리한다. 이번 문서는 코드 확인에 따른 연결안이다. 실제 관리자 화면이나 새 앱 문의 기능을 구현·배포했다는 뜻은 아니다.

## 확인한 현재 코드

- 새 도티모티 Preview49: 설정의 문의하기는 아직 미연결 안내다. 문의 접수·내 문의 목록·답변 확인 화면을 연결해야 한다.
- 기존 API: SupportTicket 모델과 mySupportTickets/supportTicket/createSupportTicket/replySupportTicket/adminSupportTickets/adminReplySupportTicket/updateSupportTicketStatus/isAdminViewer가 존재한다.
- 상태: 접수 OPEN, 처리 중 IN_PROGRESS, 답변 완료 ANSWERED, 종료 CLOSED. 사용자/관리자 메시지를 같은 문의의 대화로 저장한다.
- 권한: 본인은 자신의 문의를 조회하고 답장한다. 관리자 목록·답변·상태 변경은 서버의 requireAdminViewer로 검증한다. 프런트엔드 메뉴 숨김을 접근 제어로 삼지 않는다.
- 관리자 답변 시 SUPPORT 알림을 만드는 코드가 있다. 새 앱의 문의 화면과 해당 알림 대상 이동을 연결·검증해야 하며, 휴대폰 푸시 전달까지 확인된 것으로 표현하지 않는다.
- 공개 GraphQL 스키마에서 문의 조회/쓰기 API가 존재하고 비로그인 isAdminViewer=false임을 확인했다. 실제 사용자 문의·관리자 목록을 조회하거나 권한 설정/DB를 변경하지 않았다.

## 권장 구성

1. 앱: 설정 → 문의하기 → 분류·제목·내용 작성 → 접수 확인. 내 문의 목록에서 상태와 답변·추가 질문 확인.
2. 웹 관리자: 담당자 로그인 → 문의 목록(미답변/처리 중/답변 완료) → 문의 상세 대화 → 답변 저장·상태 변경. 첫 단계에서는 담당자 배정·첨부 파일·자동 답변을 덧붙이지 않아도 된다.
3. 서버: 기존 계정·관리자 권한과 문의 API 재사용. 조회/쓰기의 소유권·관리자 권한, 입력 제한, 중복 전송과 오류 재시도를 실제 통합 검사한다. 답변 등록은 명시적인 전송으로만 수행한다.
4. 공개 홈페이지: 제품 소개와 관리자 업무를 구분한다. 관리자 UI의 주소가 알려져도 문의 데이터는 로그인·서버 권한 검사 없이 읽을 수 없어야 한다. 비밀번호·관리자 토큰을 정적 사이트 소스에 넣지 않는다.
5. 운영 전 확인: 담당자 계정/로그인 방식, 브라우저에서 신뢰되는 HTTPS API 주소, 관리자 전용 호스팅 경로를 확정한다. 공개 소개 페이지 추가만으로 문의 접수가 가능해지는 것은 아니다.
